# ZFS 存储管理平台 · 部署文档

> 版本 v1.0.0 · 适用:存储节点 Debian 13(trixie);Manager 任意 Linux(本方案与 Agent 同机)。
> 一键安装器:deploy/install.sh(打包件内附带),或按本手册手工分步。

## 1. 前置条件与端口

| 项 | 要求 |
|---|---|
| 存储节点 | Debian 13+,内核含 target_core_mod/iscsi_target_mod,ZFS ≥ 2.3(zfsutils-linux) |
| 磁盘 | 建议整块空白盘直通给 ZFS(安装器不自动建池,由平台"新建池"向导完成) |
| 内存 | 建议 ≥ 4G(重删/大池另计);swap 可缓解 |
| 端口 | Manager 8080(可改)、Agent 9090 仅本机回环、iSCSI 3260、PostgreSQL 5432 |

## 2. 一键安装(bundle 方式,推荐)

```bash
# 解包(以 root 运行)
tar -xzf zfs-platform-1.0.0.tar.gz -C /opt
cd /opt/zfs-platform-1.0.0
./deploy/install.sh                      # 默认:安装依赖→本机 PG 建库→生成配置→systemd 启动
```

可用环境变量(缺省值见括号):

| 变量 | 说明 |
|---|---|
| PREFIX=/opt/zfs-platform | 安装目录(重装/换目录请保持一致) |
| MGR_PORT=8080 / AGENT_PORT=9090 | 服务端口(冲突时改) |
| DB_NAME=zfsmgr / DB_USER=zfsmgr / DB_PASS | 本机 PG 库;设 DB_URL 则跳过自动建库 |
| INSTALL_AGENT=1 | 0 时仅装 Manager(不装 zfs/LIO/python 依赖) |
| NO_START=1 | 仅安装不启动(用于预演) |
| UNIT_SUFFIX= | systemd 单元名后缀(同机多实例,如 `-t` → zfs-manager-t) |

安装完成输出:访问地址/默认账号(admin/admin123,首次登录后请改)/节点注册状态。

### 验证

```bash
curl -s http://127.0.0.1:8080/api/v1/auth/login -X POST -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}' | jq .ok
systemctl status zfs-manager zfs-agent
```

登录 Web → 节点应显示"在线";「新建池」向导整盘建池(会自动过滤含文件系统/已分区盘)。

## 3. 手工部署(开发机/调试)

等价于 install.sh 的步骤:

1) 依赖(存储节点):`apt install zfsutils-linux python3-rtslib-fb targetcli-fb \
   python3-fastapi python3-uvicorn xfsprogs ntfs-3g open-iscsi postgresql nodejs npm git jq curl`
   (离线/内网建议先切换中科大镜像:mirrors.ustc.edu.cn)。
2) 放置代码到 $PREFIX(manager 二进制 + agent/ + deploy/),`chmod -R a+rX`。
3) PG 建库:`sudo -u postgres psql -c "CREATE ROLE zfsmgr LOGIN PASSWORD '<pw>'" -c "CREATE DATABASE zfsmgr OWNER zfsmgr"`。
4) 生成配置:见 deploy/setup_env.sh(幂等;agent_token 必须两侧一致;advertise_addr 写存储网 IP)。
5) 安装并启动:
   ```bash
   cp deploy/zfs-manager.service /etc/systemd/system/ && cp deploy/zfs-agent.service /etc/systemd/system/
   systemctl daemon-reload && systemctl enable --now zfs-manager zfs-agent
   ```
   单元内 ExecStart 路径/端口如有改动请同步修改。
6) 建池与纳管:Web「存储池→新建池」(布局/参数向导)或 CLI `zpool create tank /dev/sdX`(平台自动发现入库)。

## 4. 配置说明

| 文件 | 关键字段 |
|---|---|
| /etc/zfs-platform/manager.toml | listen(缺省 `127.0.0.1:8080`)、db_url_file、agent_token_file、data_key_file、poll_seconds |
| /etc/zfs-platform/agent.toml | listen(127.0.0.1)、manager_url、node_name、advertise_addr、state_file、agent_token_file |
| /etc/zfs-platform/{pg.dsn,agent.token,data.key} | 敏感项文件,权限必须 0600(过宽将拒绝启动) |

> 旧版 `manager.json` / `agent.json` 在首次以 TOML 配置启动时自动迁移(密钥写入 0600 文件,原文件改名 `.bak`);未知键会拒绝启动。
> 访问方式(基线):应用仅监听回环,由入口代理对外。当前实现:`deploy/nginx-runstor.conf.example` 以 **TLS 8443** 反代(自签证书 + HSTS/XCTO/XFO/CSP + gzip);生产请替换受信证书,或改用 Caddy 并启用 `encode zstd gzip`。
> 运维端点:`/healthz`、`/readyz`(含 DB 探活)、`/version`(ldflags 注入)、`/metrics`(Prometheus 文本)。

LIO 持久化:/etc/rtslib-fb-target/saveconfig.json(Agent 每次变更保存,启动时恢复)。
数据目录:/var/lib/zfs-platform(agent-state 等)。

## 5. 升级

```bash
# 备份配置与数据库
cp -a /etc/zfs-platform /etc/zfs-platform.bak
sudo -u postgres pg_dump zfsmgr > zfsmgr.sql
# 用新包重跑 install.sh(幂等:保留旧 token/配置,重启服务)
./deploy/install.sh
# schema 增量:Manager 启动自动执行(含 ALTER ... IF NOT EXISTS),无需手工迁移
```

## 6. 运维速查

- 日志:`journalctl -u zfs-manager -f` / `journalctl -u zfs-agent -f`
- 状态:`make status`(开发机)或 `curl :8080/api/v1/dashboard`
- 节点离线:检查 Agent 心跳(agent.json manager_url/token)、`/var/lib/zfs-platform/agent-state.json`
- 会话无法断开:本内核 LIO 不暴露会话目录,请在发起端 `iscsiadm --logout`(平台接口会明确提示)
- 卸载:停服务 `systemctl disable --now zfs-manager zfs-agent`,删除 /etc/zfs-platform 与 $PREFIX(数据在池内,另行管理)

## 7. 安全清单

HTTPS 反代 + mTLS(P2);CHAP 密文 AES-GCM(密钥 manager.json data_key_hex);
Agent 仅回环监听;Manager 写操作均审计;销毁类操作需二次确认;e2e 脚本白名单清理。

## 8. 故障排查

| 现象 | 处置 |
|---|---|
| 启动报 PostgreSQL 不可达 | 确认 db_url/密码(/root/.zfsmgr_pgpass 或 env),PG 运行 |
| 节点离线 | agent 日志;token 是否一致;advertise_addr 仅影响 Portal 展示 |
| 建池失败"设备不可用" | 平台护栏拦截含文件系统/分区盘;确认真实空白盘 |
| CHAP 登录失败 | 确认主机 Initiator 已录 CHAP(≥12 位);ACL 由映射管理时勿手工改 |
| UI 显示占位页 | 运行 `make web-build && make deploy`(embed 自愈);勿用旧占位 dist 覆盖 |
