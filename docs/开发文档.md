# storman 存储管理平台 · 开发文档

> 配套:README.md(总览)/ docs/部署文档.md(安装升级)/ docs/使用手册.docx(面向使用者)
> 适用代码版本:0.95(2026-10,ZFS + RAID + 节点硬件)

## 1. 架构

浏览器(Vue3 + Element Plus)⇄ Manager(Go,单二进制,内嵌前端)→ PostgreSQL(元数据/审计)
⇄ Node Agent(Python/FastAPI,root,每节点一个)→ zfs/zpool CLI、内核 LIO(rtslib)与 storcli(RAID)。

- Manager 不直接操作存储:一切数据访问经 Agent(REST + X-Agent-Token);同机 Agent 监听回环,跨网 Agent
  监听存储网(需防火墙/令牌保护)。Manager 先试 `agent_addr`,失败再试 `advertise_addr`。
- 节点能力经注册上报(RAID/storcli、LIO 可用性、节点写保护);Agent 每次启动重新注册刷新能力。
- 无 rtslib 的节点自动跳过 iSCSI/FC 对账,不影响 ZFS/RAID。
- 状态对账:Manager 每 12s 轮询 Agent(zpool/zfs JSON、LIO 枚举)写库;离线>40s 标记 offline 并禁写。
- 操作风格:Manager 校验 → Agent 白名单执行 → JSON 回读校验 → 审计入库;变更类接口同步返回。

## 4. 关键设计点

- ZFS JSON 契约(zfs 2.3):读命令 `-j -p --json-int`;解析层校验 output_version;
  实测注意:pool_guid 命名、`-o` 组合属性限制(sparse 需 create -s)、creation 输出 epoch、status 体积为字符串。
- rtslib 经验:TPG `authentication` 属性需按 ACL 凭据同步(有 CHAP=1 否则 0);
  后建 ACL 需显式补 MappedLUN;会话在 `rt.sessions`(NodeACL/dict 双形态兼容);
  登出 = rmdir `tpgt_1/dynamic_sessions/<sid>`(部分内核无目录则返回明确不支持)。
- 卷名/池名/IQN/属性值全部白名单正则;mkfs 仅允许 `/sbin/mkfs.{ext4,xfs,ntfs}` 且先校验未映射/未挂载;
- RAID(storcli):只读用 `show J`/`/vall show J`/`/eall/sall show J`/`show events` 文本解析;写操作
  (create/delete/set)必须确认串且 `raid_allow_mutation=true`;建议参数全部校验,命令以 argv 列表执行
  (无 shell 拼接);写后回读 VD 数/状态。事件截断 storcli 尾部汇总并结构化 seq/time/event/raw。
- 节点写保护:`allow_mutation=false` 时 Agent 在执行任何变更 op 前统一拒绝(`READ_ONLY`);Manager RAID
  写接口另按能力返回 403(`RAID_READ_ONLY`),实现生产环境双端保护。
- 临时解锁:`POST /nodes/{id}/unlock`(admin)校验当前用户 bcrypt 口令与限速后,调用 Agent
  `mutation_unlock`;Agent 只保存内存态 `_mutation_until`,TTL 60~3600s,`mutation_state` 返回
  config/unlocked/expires/effective 字段。Manager RAID 写门禁在静态只读时查询该状态;到期或 Agent
  重启自动回锁。解锁/回锁审计,参数中的 password 经 redactParams 脱敏。
- RAID 事件分页在 Agent 内完成解析后按 page/page_size 切片(10~200),避免把全部 4000+ 条传到前端;
  控制器硬件字段取自 `storcli /cX show all J` 的 `HwCfg`(BBU/内存/ROC 温度)与 `Status`(ECC)。
- 存储池关联磁盘:前端展开池行时并行请求 `/pools/{id}/status`,从 `vdev_rows` 中取 `disk/file` 叶节点,
  以最近的 level 0 节点作为所属 vdev 分组。
- 节点硬件:`GET /nodes/{id}/hardware` → Agent `hardware` 查询;Agent 从 `/etc/os-release`、`/proc/cpuinfo`、
  `/proc/meminfo`、`lsblk -J`、`/sys/class/fc_host` 与 `lspci -Dnnk` 采集 OS/CPU/内存/物理磁盘/HBA。
  `disks()` 仅保留物理整盘前缀(sd/vd/nvme/hd/xvd/mmcblk/md),排除 zd(zvol)、nbd/rbd、loop/ram/sr;
  前端节点详情按 os.id 显示 Debian/openEuler 等官方图标。
- 破坏性操作需键入资源名二次确认(缩容/格式化/回滚/删除/销毁池);
- 审计:所有写操作记录 用户/动作/资源/参数(脱敏)/结果/耗时,只追加。
- 前端主题:MD3 亮/暗(`html[data-theme]` + --my-* 语义变量),localStorage 记忆;切换在右上角。
- e2e 清理为白名单(e2e-host/tank/vol-a/e2epool),**严禁**改为全量清表(2026-09 曾因全量复位误删用户主机档案)。

## 5. 主要 API(prefix /api/v1,鉴权 Bearer)

认证 `auth/login|logout|me`;节点 `nodes*`(Agent 自动注册/心跳);池
`pools`(GET/POST 高级布局/status/scrub/DELETE);数据集 `datasets`
(GET/POST 卷与文件系统/clone/resize/format/properties/DELETE);快照
`datasets/{id}/snapshots`、`rollback`、`/snapshots/{id}`;iSCSI `targets`
(建/删/LUN/ACL/会话断开);`hosts`、`mappings`(一键映射自动建删专用 Target);
`audit-logs`、`users`(admin)、`dashboard`。RAID(经 Agent 实时采集):
`GET nodes/{id}/raid/controllers`、`.../controllers/{cid}/{vds,pds,events}`;
`POST .../raid/vds`、`PATCH|DELETE .../raid/vds/{vd}`(确认串 + 只读能力门禁);
`GET nodes/{id}/mutation`、`POST nodes/{id}/unlock|lock`(管理员口令二次校验,TTL 自动回锁);
`GET nodes/{id}/hardware`(OS/CPU/内存/磁盘/HBA 实时采集)。
RAID 事件 `.../events?page=&page_size=`;池磁盘复用 `pools/{id}/status`。
详见 e2e/smoke.sh 的调用样例。
