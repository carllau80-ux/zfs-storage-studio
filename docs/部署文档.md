# storman 存储管理平台 · 部署文档

> 版本 0.94 · 适用:Debian 13 / openEuler 24.03 等 Linux;Manager 与 Node Agent 可同机或分机。
> 一键安装器:`deploy/install.sh`;手工部署见第 3 节。

## 1. 前置条件与端口

| 项 | 要求 |
|---|---|
| 存储节点 | Linux,内核含 ZFS(≥ 2.3);iSCSI/FC 需 `target_core_mod` + rtslib(可选) |
| RAID 节点 | `storcli64`(默认 `/opt/MegaRAID/storcli/storcli64`)+ MegaRAID 控制器,root 可执行 |
| 磁盘 | ZFS 建议整块空白盘;平台建池向导会过滤含文件系统/分区/挂载的设备 |
| 内存 | 建议 ≥ 4G(重删/大池另计) |
| 端口 | Manager 8080(默认仅回环)、Agent 9090(本机)或 19090(跨网节点)、iSCSI 3260、PostgreSQL 5432 |
| 网络 | 跨网 Agent 需能访问 Manager 的 HTTPS 入口(如 8443),并信任其证书 |

## 2. 一键安装(bundle 方式,推荐)

```bash
# 解包(以 root 运行)
tar -xzf storman-0.94.tar.gz -C /opt
cd /opt/storman-0.94
./deploy/install.sh     # 安装依赖→本机 PG 建库→生成配置→systemd 启动
```

缺省安装到 `/opt/storman`、配置 `/etc/storman`,服务 `storman-manager` / `storman-agent`。
历史部署(`/opt/zfs-platform`、`zfs-manager`/`zfs-agent` 单元、库名 `zfsmgr`)保持兼容,不会被改名。

| 变量 | 说明 |
|---|---|
| PREFIX=/opt/storman | 安装目录(重装保持一致) |
| MGR_PORT=8080 / AGENT_PORT=9090 | 服务端口 |
| DB_NAME=zfsmgr / DB_USER=zfsmgr / DB_PASS | 本机 PostgreSQL;设 DB_URL 则跳过自动建库 |
| INSTALL_AGENT=1 | 0 时仅装 Manager(不装 zfs/LIO/python 依赖) |
| NO_START=1 | 仅安装不启动 |
| UNIT_SUFFIX= | systemd 单元名后缀(多实例,如 `-t`) |

安装完成输出初始管理员口令文件:`/etc/storman/admin.secret`(0600,首次登录后立即修改)。
所有凭据参数化:仓库不含口令/API key;PG DSN、Agent 令牌、数据密钥、管理员口令均为 0600 文件。

### 验证

```bash
curl -s http://127.0.0.1:8080/api/v1/auth/login -X POST -H 'Content-Type: application/json' \
  -d "{\"username\":\"admin\",\"password\":\"$(cat /etc/storman/admin.secret)\"}" | jq .ok
systemctl status storman-manager storman-agent
```

登录 Web → 节点应“在线”;「新建池」向导建池(自动过滤不可用盘);「RAID」页按节点能力显示控制器。

## 3. 手工部署(开发机/调试)

1) 依赖(存储节点):`apt install zfsutils-linux python3-fastapi python3-uvicorn jq curl`
   ;iSCSI 追加 `python3-rtslib-fb targetcli-fb open-iscsi`;NFS/SMB 追加 `nfs-kernel-server samba`。
2) 放置程序:Manager 二进制到 `$PREFIX/bin/storman-manager`,`agent/` 到 `$PREFIX/agent`,`deploy/` 保留。
3) PG 建库:`sudo -u postgres psql -c "CREATE ROLE zfsmgr LOGIN PASSWORD '<pw>'" \
   -c "CREATE DATABASE zfsmgr OWNER zfsmgr"`。
4) 生成配置(参考 `deploy/setup_env.sh`;`agent.token` 两侧一致)。
5) 安装单元:
   ```bash
   cp deploy/storman-manager.service /etc/systemd/system/
   cp deploy/storman-agent.service /etc/systemd/system/
   systemctl daemon-reload && systemctl enable --now storman-manager storman-agent
   ```
   单元内 ExecStart 路径/配置路径如变更请同步修改。
6) 建池:`zpool create tank /dev/sdX`(平台自动发现)或 Web 向导。

## 4. 配置说明

| 文件 | 关键字段 |
|---|---|
| /etc/storman/manager.toml | listen(缺省 `127.0.0.1:8080`)、db_url_file、agent_token_file、data_key_file、poll_seconds |
| /etc/storman/agent.toml | listen、manager_url、node_name、advertise_addr、state_file、agent_token_file、allow_mutation、raid_storcli_path、raid_allow_mutation |
| /etc/storman/{pg.dsn,agent.token,data.key,admin.secret} | 敏感项,权限必须 0600(过宽拒启) |

> 旧版 `manager.json`/`agent.json` 首次以 TOML 启动时自动迁移(密钥写 0600 文件,原文件改名 `.bak`);
> 未知键拒绝启动。运维端点:`/healthz`、`/readyz`、`/version`、`/metrics`。
> 对外入口:`deploy/nginx-runstor.conf.example`(TLS 8443 + HSTS/XCTO/XFO/CSP + gzip);生产替换受信证书,
> 或使用 Caddy 并启用 `encode zstd gzip`。

LIO 持久化:`/etc/rtslib-fb-target/saveconfig.json`(Agent 变更即保存、启动恢复;无 rtslib 的节点自动跳过)。
数据目录:`/var/lib/storman`(Agent 状态)。

## 5. RAID 管理与只读 Agent(生产/验证)

### 5.1 节点配置

Agent 默认 `raid_allow_mutation=false`(RAID 仅只读)。生产/验证节点追加:

```toml
allow_mutation = false          # 所有 ZFS/RAID/共享/LIO 写操作在 Agent 侧拒绝(READ_ONLY)
raid_allow_mutation = false     # RAID 写操作单独禁用(默认)
raid_storcli_path = "/opt/MegaRAID/storcli/storcli64"
```

`allow_mutation` 缺省为 `true`(开发节点);设为 `false` 后 Manager 仍可查询,任何 `POST /api/v1/op`
都会在 Agent 执行前返回 `READ_ONLY`,防止生产数据被误改。能力上报包含
`capabilities.raid={available,allow_mutation,storcli}` 与 `capabilities.allow_mutation`。

管理员可在 Web「RAID」页点击「输入密码临时解锁」,输入**当前登录账号**口令并选择 5/15/30/60 分钟:
- Manager 重新校验口令(RBAC 要求 admin,失败计入限速)后调用 Agent,仅设置内存态解锁,不修改配置;
- 解锁期间节点级 ZFS/RAID 写操作放开,Manager 的 RAID 写门禁同步放行;
- 到期自动回锁,或在页面点击「立即回锁」;Agent 重启/配置重载也会恢复只读;
- 解锁/回锁均写审计,口令字段自动脱敏。

RAID 日志为服务端分页接口:`/raid/controllers/{cid}/events?page=2&page_size=50`(10~200/页);
控制器 BBU/温度/内存来自 storcli 的 `HwCfg/Status` 段,BBU 缺失时显示「缺失(未配置)」。

### 5.2 跨网 Agent 注册(示例:192.168.2.128)

1) 复制 `agent/` 到 `/opt/storman/agent`,创建 venv 并安装 `fastapi`、`uvicorn`(无 rtslib 也可运行)。
2) `/etc/storman/agent.token` 与 Manager 的 `agent.token` 保持一致(0600)。
3) `/etc/storman/agent.toml`:
   ```toml
   listen = "0.0.0.0:19090"
   manager_url = "https://192.168.13.38:8443"
   node_name = "prod2128"
   advertise_addr = "192.168.2.128:19090"
   state_file = "/var/lib/storman/agent-state.json"
   agent_token_file = "/etc/storman/agent.token"
   allow_mutation = false
   raid_storcli_path = "/opt/MegaRAID/storcli/storcli64"
   raid_allow_mutation = false
   ```
4) 将 Manager 的 TLS 证书加入节点信任库(openEuler):
   `cp manager.crt /etc/pki/ca-trust/source/anchors/ && update-ca-trust`。
5) 安装 `storman-agent.service` 并启动。Manager 会依次尝试 `agent_addr` 与 `advertise_addr` 回连;
   Agent 每次启动重新注册以刷新能力。

### 5.3 验收(只读节点)

```bash
# 控制器/VD/PD/事件(经 Manager,需登录令牌)
curl -s -H "Authorization: Bearer $TOK" http://127.0.0.1:8080/api/v1/nodes/4/raid/controllers
curl -s -H "Authorization: Bearer $TOK" http://127.0.0.1:8080/api/v1/nodes/4/raid/controllers/0/vds
# 写操作应被 Manager 拒绝(403 RAID_READ_ONLY),Agent 日志无 storcli 写调用
curl -s -o /dev/null -w '%{http_code}\n' -X POST -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' \
  -d '{"controller":0,"level":"5","drives":["252:0"],"confirm":"CREATE 5"}' \
  http://127.0.0.1:8080/api/v1/nodes/4/raid/vds
# 临时解锁(管理员口令)/回锁(不执行任何存储写操作)
curl -s -X POST -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' \
  -d '{"password":"<当前管理员口令>","ttl_s":900}' http://127.0.0.1:8080/api/v1/nodes/4/unlock
curl -s -X POST -H "Authorization: Bearer $TOK" http://127.0.0.1:8080/api/v1/nodes/4/lock
```

生产环境严禁执行创建/删除/属性修改验收;如需验证写路径,应在独立测试节点进行。

## 6. 升级

```bash
cp -a /etc/storman /etc/storman.bak
sudo -u postgres pg_dump zfsmgr > zfsmgr.sql
# 新包重跑 install.sh(幂等:保留 token/配置,重启服务)
./deploy/install.sh
# schema 由 Manager 启动时版本化迁移自动执行
```

历史部署升级到 storman 包时,如需保留 `/opt/zfs-platform` 与 `zfs-*` 单元,设置
`PREFIX=/opt/zfs-platform CFG_DIR=/etc/zfs-platform` 并手工沿用原单元,避免双实例。

## 7. 运维速查

- 日志:`journalctl -u storman-manager -f` / `journalctl -u storman-agent -f`(历史环境为 zfs-*)
- 状态:`curl :8080/healthz`、`/metrics`;开发机 `make status`
- 节点离线:检查 Agent 心跳(manager_url/token/证书)、`/var/lib/storman/agent-state.json`
- RAID 不可见:确认 `storcli64` 路径可执行、控制器存在,重启 Agent 刷新能力
- RAID 硬件信息为空:确认 Agent 使用的 storcli 支持 `show all J`;BBU 未配置时显示「缺失(未配置)」
- 会话无法断开:在 Initiator 侧 `iscsiadm --logout`(平台会明确提示)
- 卸载:停服务并删除配置与 PREFIX(数据在池内,另行管理)

## 8. 安全清单

HTTPS 反代 + 安全头;CHAP 密文 AES-GCM;Agent 令牌 SHA-256 存库;Agent 默认仅回环(跨网需评估暴露面,
至少限制来源与保持共享令牌机密);Manager 写操作全审计;销毁/RAID 写需二次确认;
生产节点设置 `allow_mutation=false`;e2e 白名单清理。

## 9. 故障排查

| 现象 | 处置 |
|---|---|
| 启动报 PostgreSQL 不可达 | 检查 db_url_file 指向的 DSN、PG 运行状态 |
| 节点离线 | Agent 日志;token 是否一致;跨网地址/证书是否可达 |
| 建池失败“设备不可用” | 平台护栏拦截含文件系统/分区盘;确认真实空白盘 |
| RAID 节点显示“未检测到 storcli” | 校正 `raid_storcli_path`,确认 root 可执行,重启 Agent |
| RAID 写操作 403 | 节点为只读;管理员可在 RAID 页输入本人口令临时解锁,或调整配置后重启 Agent |
| CHAP 登录失败 | 主机 Initiator 已录 CHAP(≥12 位);映射管理的 ACL 勿手工改 |
| UI 显示旧页面 | 重新构建前端并内嵌到 Manager,或确认使用了新二进制 |
